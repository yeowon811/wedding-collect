# AI 상담 평가 기록

같은 질문 세트로 규칙 기반과 Gemini를 비교하고, 틀린 부분을 고친 뒤 다시 측정한다.

- 질문 세트: `test/eval/understanding_cases.dart` (42개: 정책 12, 예식장 5, 업체 9, 예산·일정·추천·기타 8, 되묻는 중의 답 8)
- 실행: `flutter run -d chrome --dart-define-from-file=secrets.json -t test/eval/eval_main.dart`
  (일부만: `--dart-define=EVAL_ONLY=P03,P07`, 이어서: `--dart-define=EVAL_FROM=V01`)
- 보고서: `python -I tools/eval_report.py <flutter run 출력 파일> <이름>`

## ① 질문 이해 (2026-11-16, gemini-3.5-flash-lite)

| 회차 | 바꾼 점 | 규칙 기반 | Gemini 단독 | 앱 실제 (Gemini + 규칙 보완) | 응답 시간 (중앙값 / 최대) | 보고서 |
|---|---|---|---|---|---|---|
| v1 | 처음 연결 | 29/42 (69%) | 41/42 (97%) | 측정 전 | 1.4초 / - | [v1](understanding_report_v1.md) |
| v2 | 나이 범위 규칙을 프롬프트에 명시 ("30대 중반" = 33~36) | 29/42 | 40/42 | 측정 전 | **6.7초 / 12초(시간 초과 1건)** | [v2](understanding_report_v2.md) |
| v3 | 생각(thinking) 단계를 최소로: 단순 추출이라 응답 속도 우선 | 29/42 | **42/42** | **42/42** | **1.5초 / 2.3초** | [v3](understanding_report_v3.md) |

### 알게 된 것
- **규칙 기반이 틀린 13건**은 모두 표현이 다양한 경우: 한글 숫자("스물아홉", "삼천만원", "백명"), 정해 둔 단어가 없는 질문("나라에서 돈 주는 거", "식 올릴 데"), 짧은 답("아직 안 했어요", "집은 없어요"), 단어가 겹치는 경우("결혼식 사진" → 식대로 오인).
- **Gemini가 틀린 것**: v1의 "30대 중반"(30~34로 읽음, 앱 기준은 33~36) → 프롬프트에 기준을 적어 해결. v2의 하객 수 누락 1건은 앱에서는 규칙 결과로 보완되어 실제 답변에는 영향 없음.
- **응답 시간**: v2에서 Gemini가 매번 "생각"을 하느라 최대 12초까지 걸려 1건이 시간 초과(→ 규칙 기반으로 대체됨). 생각 단계를 최소로 줄이자 정확도는 그대로, 최대 2.3초로 줄어듦.
- 장애 대응 확인: App Check 설정 전에는 Gemini 호출 42건이 모두 거절됐지만 상담은 규칙 기반으로 계속 동작함.

## ⑤ 답변 문장 (2026-11-16, gemini-3.5-flash-lite)

앱이 데이터로 만든 답변(조회 결과)을 Gemini가 질문에 맞게 다시 쓴다. 질문 15개(서울 예비부부 / 경기 신혼부부 두 가지 내 정보).

- 실행: `flutter run -d chrome --dart-define-from-file=secrets.json -t test/eval/answer_eval_main.dart` → `python -I tools/answer_eval_report.py <출력> <이름>`
- 자동 검사 두 가지를 **모두 통과한 Gemini 답변만 앱에 표시**하고, 하나라도 걸리면 원래 문장을 보여준다.
  - 숫자 검사: 답변의 숫자가 모두 조회 결과에 있어야 함
  - 표시어 검사: "시연용"·"가상"·"예비부부"·"신혼부부"·"기관"이 조회 결과에 없는데 답변에 나오면 안 됨

| 회차 | 바꾼 점 | 숫자 검사 | 표시어 검사 | 주의 문구 유지 | Gemini 문장이 보이는 비율 | 응답 시간 (중앙값 / 최대) | 보고서 |
|---|---|---|---|---|---|---|---|
| v1 | 처음 지시문 | 14/15 | **4/15** | 11/11 | **4/15** | 1.4초 / 2.4초 | [v1](answer_report_v1.md) |
| v2 | 지시문 수정 + 표시어 검사 추가 | 15/15 | 15/15 | 11/11 | **15/15** | 1.5초 / 2.0초 | [v2](answer_report_v2.md) |

### 알게 된 것 (사람이 15개 답변을 모두 읽고 확인)
- v1에서 Gemini가 **실제 예식장·정책 데이터에 "시연용 가상 데이터"라는 문구를 붙임** (5건), **신혼부부에게 "예비부부님"이라고 부름** (4건), 업체 답변에 관계없는 "기관 확인 필요"를 붙임 (2건), "30건 찾음"을 "3건 찾음"으로 바꿈 (1건, 숫자 검사로 차단).
  - 원인: 지시문에 "시연용 가상 데이터", "기관 확인 필요"를 예시로 적었고, 상담사 역할을 "예비부부를 돕는"으로 적어 그대로 따라 씀.
  - 해결: 지시문에서 예시 문구를 빼고 "조회 결과에 있는 주의 문구만 옮기기, 호칭 쓰지 않기, 건수는 그대로"로 바꿈. 지시문이 실패해도 막도록 **표시어 검사를 코드로 추가** (`GeminiClient.termsAreGrounded`, 테스트 `test/gemini_guard_test.dart`).
- v2 남은 문제 1건: W07에서 3곳을 보여 주면서 "12곳 중에서 6곳을 골랐어요"라고 씀(6은 하객 수용 가능 수라 숫자 검사를 통과). 자동 검사로 막기 어려운 유형이라, 숫자가 중요한 내용은 카드(앱이 직접 만든 값)로 함께 보여준다.
- Gemini와 관계없이 앱 답변에서 발견: 예식일까지 99일 남았는데 "지금 할 일"에 D-365·D-330 항목이 지났다는 표시 없이 나옴 → **고침**: 권장 시기가 지난 일은 "(권장 D-365, 시기 지남)"으로 표시하고 개수를 안내 (`consult_agent.dart` `_scheduleAnswer`, 테스트 `test/schedule_answer_test.dart`).
