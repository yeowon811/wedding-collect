## Phase 1 (P0): 라이브 버그·레이아웃
1. **상단 컨텍스트 바 즉시 동기화:** 대화·칩으로 반영된 프로필(지역·나이·예식일·하객·총예산·주택)이 즉시 위쪽에 보인다. 텍스트 대신 조건 칩 줄 `[서울 ✕] [하객 150명 ✕] [총예산 3,000만원 ✕] [+ 조건 수정]`, 칩마다 개별 해제
2. **헤더 정리:** 중복된 "내 정보"(파란 사람) 아이콘 제거. 오른쪽은 `[공유]`(Phase 3) · `[새 상담]` · `[내 계정]`만, 서로 구분되는 아이콘
3. **사전 입력 폼:** 총예산은 항상 '만원' 단위 표시 + 입력 중 한글 금액 보조 표시(예: 3,000만 원). 개별 [확인]을 안 눌러도 하단 [이 정보로 상담 시작]/[저장하고 다시 추천받기]가 입력칸의 값을 자동으로 저장
4. **데스크톱(>768px):** AI 상담 본문(바·목록·입력창)을 가운데 `maxWidth: 760`
5. **가림 방지:** "출처 보기 · 어떻게 찾았나요"를 펼치면 `Scrollable.ensureVisible(..., alignmentPolicy: keepVisibleAtEnd)`로 펼친 영역 전체가 입력창 위에 보이게. 목록 아래 여백 = 입력 바 + 후속 칩 + 24px. 구조는 `Column` + `Expanded(ListView)` + `SafeArea` 입력 바
6. **웹 사용성:** 채팅 `SelectionArea`(복사), 모바일 키보드가 올라오면 하단 5탭 숨김, 한글 조합 중(`!composing.isCollapsed`) 엔터 전송 보류, 상세·탭 이동 후 채팅 스크롤·상태 유지

## Phase 2 (P1): 도메인 로직·설명 가능한 AI
1. **총예산 vs 대관료 분리:** "예산 3000만원"을 대관료 상한(`max_fee_won`)으로 쓰지 않는다. 프로필·검색 조건에서 총예산과 희망 대관료를 구분
2. **예상 총 예식비(TCO) 병기:** "대관료 무료"만 단독 표기 금지. 하객 수(없으면 150명) 기준 대관료 + 식대 + 기본 연출·꽃장식 예상 범위를 함께 (예: "대관료 무료 · 식대·꽃장식 별도, 150명 기준 예상 총 X~Y만원"). 숫자는 참고 단가표로 계산, "추정" 표시
3. **"어떻게 찾았나요" 사용자 말로:** 함수명(`search_venues`)·JSON·ms·내부 코드(K1~K8)를 화면에 출력 금지. 3단 검증 요약으로:
   1) 검증 배지 "공공데이터 및 자격 규칙 검증 완료"
   2) 걸러진 과정 "서울 74곳 → 요금 확인 61곳 → 하객 150명 수용 22곳" (제외 건수·이유)
   3) 출처 + 충족한 조건 / 미입력·현장 확인 필요 조건 구분
   - 내부 기록은 지우지 말고 개발·평가용으로만 보관 (규칙 검증 근거)
4. **사진 대신 속성 배지:** 외부 이미지 실패 시 대체 화면 통일. 카드 위쪽에 데이터 기반 속성 배지(실내 대강당·야외/잔디·외부 케이터링·주차 가능·대관료 무료)

## Phase 3 (P2): 공유·미니 폼·담기
1. **파트너에게 공유:** 헤더·결과의 [공유] → 내 조건 + 추천 TOP 3 요약을 카톡용 글로 복사 + "카카오톡 공유용 상담 요약이 복사되었어요!" 안내. 조건이 담긴 링크(`?tab=ai&sido=서울&guests=150&budget=3000`)로 들어오면 같은 조건 자동 설정
2. **채팅 안 미니 폼:** 정책처럼 여러 조건(거주지·나이·혼인신고·주택)이 필요한 질문은 하나씩 되묻지 않고 칩 묶음 카드 한 장 → [조건 적용하고 결과 보기]로 한 턴에 받음
3. **카드에서 바로 담기·복사:** 카드에 [복사]·[+ 담기]. 담기는 화면 이동 없이 체크리스트에 추가 + "체크리스트에 추가했어요 [보러가기]"
